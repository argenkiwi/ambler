ambler generates ambler-rs (default), ambler-ts or ambler-py projects. The target is resolved once in main.rs by scaffold::target::resolve: --target flag, then AMBLER_TARGET, then marker files (ambler.ts + package.json -> TS, Cargo.toml + src/engine.rs -> Rust, pyproject.toml + src/<package>/engine.py -> Python; skipped for `new`, whose cwd is the parent), then Rust. resolve takes a read closure (not just exists) because Python's package comes from pyproject.toml. It travels in State behind HasTarget, so per-verb strict args::parse never sees --target. Target is an enum, not a trait: `match` at the few call sites (paths, checks, unfinished markers, formatter via Change.format: Option<Target>) is simpler, and planning nodes branch into plan_rust/plan_ts/plan_py. Watch for if/else sites that test `== Target::TypeScript` and fall through to Rust: the compiler won't catch a new variant there, so they were turned into matches (guides.rs, pave::outcomes_line, plan_util). Language-neutral pieces live in scaffold/{walk,lint,context}.rs; scaffold/rust/ uses syn, scaffold/ts/ uses oxc (pinned to 0.75 by rust-version 1.85), scaffold/py/ uses rustpython-parser 0.4 (Ruff's own parser crates need rust 1.97+). context.rs AGENTS/CLAUDE/SKILL are emitted to every target, so they must stay target-neutral.
