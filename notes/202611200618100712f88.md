Unlike a generated walk, ambler's own walks share walks::State (args, plan, message), so node tests can use testing::State with the shared Fake. pave adds one field, paving: scaffold::pave::Paving (settings, last check result and tail, current task and label, repair/retry/repeat/iteration counters), behind a single HasPaving trait, the same way HasPlan wraps Plan. Task selection and the guards (Paving::decide) are pure functions in scaffold/pave.rs, ported from the ambler-loop.sh gist, so they are unit-tested without I/O; the nodes only read files and call git. Guard order matters: Done first, then the repair budget (Exhausted -> roll back once, then Stuck), then no-progress (same label 3x while green), then max iterations.
