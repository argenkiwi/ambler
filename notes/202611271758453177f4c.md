All targets now share one rule for how a node declares the state it needs, written down in docs/tooling_protocol.md §3: every contract is a Has<Field> covering exactly one field, declared only in the project state registry (Rust src/nodes/mod.rs, Python nodes/__init__.py, TypeScript nodes/state.ts), and nodes only compose contracts (Rust bounds, a Python local State(HasA, HasB, Protocol), TS `export interface State extends HasA, HasB {}`), never declaring fields of their own. TypeScript previously had each node repeat its fields in its own State interface with no registry; it moved to Has* so a field type lives in one place and `--state f` resolves the same way in every CLI. Rust read-only contracts (no _mut) are allowed; a contract may wrap a struct-typed field (HasPaving stays), but not two fields or behaviour methods (azk HasQueue/HasSearch/HasTopic, pide HasServer need migrating). Each native check enforces it: state-traits (rs), state-protocols (py), state-contracts (ts). Gotcha: Biome accepts `interface State extends HasCount {}` without a noEmptyInterface ignore, so the old biome-ignore on empty State is no longer needed.
