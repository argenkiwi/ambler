So that agents in a container with only the project's dev dependencies (pide/Pi) can read the conventions, the guides to node, util, walk, check, conventions, node-design, testing and spec moved out of ambler's binary into ambler-rs (include_str), ambler-ts (Bun text imports, guides/ in package.json files) and ambler-py (package data via importlib.resources), behind a new ATP verb `<cli> help [topic]`. `ambler help <topic>` hands those topics to the native CLI through the delegate walk (guides::is_native, dispatched in main.rs); ambler still prints the overview, new, pave, help and agents itself. Project context files are now templates (templates/AGENTS.md, templates/SKILL.md) with <cli>/<engine>/<setup> placeholders rendered per target by scaffold::context::render, so they never tell the agent to run the global ambler; the repo's .agents/skills/ambler/SKILL.md is now only the global skill (GLOBAL_SKILL). Gotcha: guides.rs's unknown_mentions test flags any 'ambler <word>' in a guide, so prose like 'ambler hands' fails ambler check. Rejected: a Pi package (third copy, Pi-only) and static skill copies (drift from the pinned CLI).
