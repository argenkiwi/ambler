pave's CheckProject node re-executes current_exe() with `check` instead of calling the check walk's nodes directly. Two reasons: the verify node streams cargo to the inherited terminal, but pave needs the combined stdout+stderr in a log (kept in <git-dir>/amble-pave-check.log so it is never committed) to tail into repair prompts; and it must set CARGO_TARGET_DIR (AMBLE_PAVE_TARGET, default target/amble-pave) only for its own builds so a host build does not clobber a container agent's target/. Both streams share one File handle (try_clone) so their order is preserved. The agent is run as `sh -c '<cmd> "$1"' amble <prompt>`, so --agent can carry flags and the prompt is always exactly one argument, with no quoting or word-splitting issues; this is Unix-only.
