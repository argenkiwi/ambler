A Python project's files live under src/<package>/, so unlike Rust and TypeScript its paths depend on the project. Target::Python holds the package as a &'static str, interned once with Box::leak in target::resolve, which keeps Target Copy + Eq + Ord and lets tests write Target::Python { package: "app" }. The package is [project] name from pyproject.toml in snake_case (read by a small line reader, no TOML crate); detection also needs src/<package>/engine.py. `--target py` parses to an empty package that resolve fills in, except for `new`, where plan_project uses the project name. Because the variant has data, compare languages with Target::same_language, and ask whether the folder is a project with Target::is_project (manifest + engine), as plan_pave now does. Target::engine() and nodes_folder() return String for the same reason.
