`ambler new` no longer copies a CLI into projects (templates/ts/cli.ts and templates/py/cli.py are gone). Instead each project declares the native CLI as a dev dependency from GitHub: ambler-ts in package.json, which ambler runs as `bun node_modules/.bin/ambler` (gotcha: a bare `bun run ambler` resolves the project's own ambler.ts before the bin, runs the library and silently exits 0 — argenkiwi/ambler-ts#28 — so the TS template also declares an `"ambler": "ambler"` script, which `bun run` prefers to files, for humans typing `bun run ambler`), ambler-py in the uv dev group plus [tool.uv.sources] (`uv run ambler`), and for Rust an `xtask` crate depending on ambler-rs behind a `cargo ambler` alias, because Cargo cannot depend on a binary. Because nothing lands on the PATH, the ATP rule against an executable called `ambler` now only forbids global installs. The runner still accepts older projects (cli.ts, run as `bun cli.ts`; `.venv/bin/ambler-cli`) and a global cargo-ambler. When the CLI is missing, the diagnostic names both the install step (bun install / uv sync / cargo build) and the add-the-dependency command, since ambler cannot tell declared-but-uninstalled from undeclared without reading manifests. The ignored e2e tests in walks/new.rs fetch the CLIs from GitHub, so they only pass once the native repos' changes are pushed.
