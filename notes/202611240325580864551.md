`ambler new` no longer copies a CLI into projects (templates/ts/cli.ts and templates/py/cli.py are gone). Instead each project declares the native CLI as a dev dependency from GitHub: ambler-ts in package.json (`bun run ambler` runs node_modules/.bin/ambler), ambler-py in the uv dev group plus [tool.uv.sources] (`uv run ambler`), and for Rust an `xtask` crate depending on ambler-rs behind a `cargo ambler` alias, because Cargo cannot depend on a binary. Because nothing lands on the PATH, the ATP rule against an executable called `ambler` now only forbids global installs. The runner still accepts older projects (cli.ts, `.venv/bin/ambler-cli`) and a global cargo-ambler. When the CLI is missing, the diagnostic names both the install step (bun install / uv sync / cargo build) and the add-the-dependency command, since ambler cannot tell declared-but-uninstalled from undeclared without reading manifests. The ignored e2e tests in walks/new.rs fetch the CLIs from GitHub, so they only pass once the native repos' changes are pushed.
